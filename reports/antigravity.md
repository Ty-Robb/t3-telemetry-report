## Executive summary of code findings

Direct code tracing confirms that T3 Code's product analytics stream (`AnalyticsService.ts`) primarily carries usage metadata, with custom model identifiers and filenames remaining possible, and that seven privacy-related commits merged on 2026-11-24 closed several real issues (provider account ID hashing, mobile device ID reuse, relay trace IP/User-Agent capture, Windows desktop opt-out reading, feedback install linking, and relay tracing opt-out gaps).

Direct code tracing also uncovers concrete implementation bugs and privacy gaps that are present in the source at `55085df2a6c384f34b37901d5dcbc5925ada1600`:

1. **Desktop server relay tracing ignores deferred shell opt-out on launch (source-supported defect).** The desktop app spawns the server before shell profile discovery finishes, and `apps/server/src/cloud/relayTracing.ts` reads `process.env` once at module import time with no dynamic gate. Setting `T3CODE_TELEMETRY_ENABLED=false` in `~/.zshrc` or Windows User environment variables leaves server-side relay tracing to Axiom active for that process until a subsequent restart loads it from `shell-environment-cache.json`.
2. **Desktop shell discovery omits `T3CODE_OTEL_SDK_DISABLED` and `OTEL_SDK_DISABLED` (source-supported defect).** Neither variable appears in `apps/desktop/src/shell/DesktopShellEnvironment.ts`, so setting either kill switch in a shell profile or Windows User registry does not disable relay tracing in GUI-launched desktop builds.
3. **Anonymous `agent.feedback` events ride in the same `/batch/` HTTP request as identified install events (source-supported defect).** `FeedbackStore.ts` queues `agent.feedback` with `{ anonymous: true }` into the shared `AnalyticsService` buffer, and `sendBatch` transmits mixed anonymous and identified events in one `POST https://ingest.t3.codes/batch/` body while keeping OS, arch, version, and WSL properties on the feedback event. This allows `ingest.t3.codes` to tie feedback directly to the sending install, contradicting `docs/user/telemetry.md`.
4. **`ownerSource: "connect"` still sends unsalted SHA-256 of the Clerk `user_id` and exposes it in WebSocket query strings (confirmed code behavior).** `Identify.ts` and `packages/client-runtime/src/authorization/remote.ts` hash the raw T3 Connect user ID with unsalted SHA-256 (`telemetryId.ts`), allowing deterministic re-identification by anyone holding the Clerk or relay Postgres user list. Clients pass `clientOwner` and `clientDevice` hashes in `/ws` URL query parameters.
5. **Opt-out coverage is fragmented and defaults are opt-out, not opt-in (confirmed code behavior).** Product analytics has no in-app UI toggle. Mobile crash reporting (`expo-observe`) and startup metrics are on by default and unaffected by `T3CODE_TELEMETRY_ENABLED` or managed policy. Hosted web (`app.t3.codes`) defaults relay tracing on before connecting to a server and has no user toggle. `T3CODE_TELEMETRY_ENABLED=false` does not stop agent activity publishing or background GitHub and npm metadata fetches.
6. **`Ty-Robb/t3-telemetry-report` (`ANALYSIS.md`) is accurate on raw row counts and the absence of prompts or emails in the dump, but contains four factual misreadings of the dump schema and omits key commits and linkability paths.** Specifically, `ANALYSIS.md` mislabels 45,505 turn/request rows carrying `createdBy` as "thread-creating events", misattributes combined `provider.turn.completed` and `provider.request.completed` `usageStatus` counts to turns alone, mixes three event types in its `connectionMethod` counts, omits two mobile device models present in `analysis.json`, and misses both the second cross-OS `distinct_id` (`e25f82654288`) and the still-active unsalted `connect` owner hash.

### Model label pass-through edge case

In [`apps/server/src/telemetry/ProviderDimensions.ts#L27-L68`](https://github.com/pingdotgg/t3code/blob/55085df2a6c384f34b37901d5dcbc5925ada1600/apps/server/src/telemetry/ProviderDimensions.ts#L27-L68), `modelLabel` maps known catalog slugs and aliases to a canonical slug and strips directory prefixes only when a model string matches `FILE_PATH` (`^(?:[/~]|\.{1,2}[/\\]|[A-Za-z]:[\\/])|\\`). Any unrecognized custom model string that is not a filesystem path is sent verbatim. If a user configures a private proxy prefix, Bedrock ARN, or custom enterprise deployment ID as a model identifier, that identifier leaves the machine in `model`, `observedModel`, `callerModel`, or `targetModel`.

## Historical versus current code changes (2026-11-24)

Inspecting the git history in `t3code-source` up to `55085df2` shows seven privacy- and telemetry-related commits merged on 2026-11-24:

1. **`4eccb0ec` (`fix(relay): traces no longer record callers' IP addresses or user agents (#42380)`).** Modifies [`infra/relay/src/http/Api.ts`](https://github.com/pingdotgg/t3code/blob/55085df2a6c384f34b37901d5dcbc5925ada1600/infra/relay/src/http/Api.ts#L239-L248) so `HttpMiddleware.tracer` sees `remoteAddress: Option.none()` and stripped `user-agent` headers (while keeping `relay.edge.colo`, `country`, `continent`, and raw Clerk `user.id`).
2. **`3380585e` (`feat(relay): delete a user's relay data when Clerk deletes the user (#42285)`).** Adds `relay_account_deletions` queue and sweep to delete a deleted Clerk user's relay records and managed Cloudflare tunnels.
3. **`482e197f` (`fix(mobile): analytics uses its own random device id (#42394)`).** Stops mobile from hashing `t3code.agent-awareness.device-id` (stored in relay Postgres) and introduces a separate `t3code.analytics.device-id` ([`apps/mobile/src/persistence/mobile-storage.ts#L12`](https://github.com/pingdotgg/t3code/blob/55085df2a6c384f34b37901d5dcbc5925ada1600/apps/mobile/src/persistence/mobile-storage.ts#L12)).
4. **`3ba003be` (`fix(desktop): Windows desktop applies the saved user telemetry opt-out (#42376)`).** Adds `T3CODE_TELEMETRY_ENABLED` to `WINDOWS_PROFILE_ENV_NAMES` and updates `windowsEnvironmentValueCommand` in `packages/shared/src/shell.ts` to read Process, User, and Machine registry scopes. Previously, Windows desktop ignored User-scoped `T3CODE_TELEMETRY_ENABLED=false`.
5. **`84e4264b` (`fix(server): analytics no longer reads or sends Codex and Claude account IDs (#42299)`).** Removes reading `~/.codex/auth.json` (`tokens.account_id`, JWT `id_token` `user_id`) and `~/.claude.json` (`userID`, `oauthAccount.accountUuid`) from [`Identify.ts`](https://github.com/pingdotgg/t3code/blob/55085df2a6c384f34b37901d5dcbc5925ada1600/apps/server/src/telemetry/Identify.ts#L1-L164). Prior to this commit, `distinct_id` prioritized `SHA-256(codex.account_id)`, then `SHA-256(claude.userID)`, then `installId`, and `install.owner_observed` emitted `openai` and `claude` hashes.
6. **`796103f4` (`fix(server): agent feedback no longer links to the install (#42398)`).** Adds `{ anonymous: true }` to `FeedbackStore.ts` and suppresses unprompted agent-written text (only sending categories unless user approves a card). Subject to Bug 3 (shared `/batch/` HTTP payload).
7. **`dc7b8802` (`fix(connect): respect relay tracing opt-outs and remove machine details (#42356)`).** Wires mobile `diagnosticsSetting` into mobile relay tracing, adds `relayTracingAllowed` to `server.getConfig` for server-opened browsers, strips `url.full` / `url.query` / `server.address` / `server.port` from client relay spans, stops sending operator `OTEL_RESOURCE_ATTRIBUTES` / `service.instance.id` hostnames in server relay spans, and updates `docs/user/telemetry.md`. Subject to Bugs 1 and 2 on desktop.

Builds lacking the relevant fixes may retain the earlier behavior. No installed versions or deployment population were inspected.

## Unknowns and limitations

The following cannot be proven from `pingdotgg/t3code` or `Ty-Robb/t3-telemetry-report` alone:

1. **Hosted `ingest.t3.codes` server implementation.** The source code for `ingest.t3.codes` is not in `pingdotgg/t3code`. Whether it logs client IP addresses, retains raw `/batch/` envelopes (enabling Bug 3 correlation), how long it retains its own copy of events, what logic sets `to_posthog: false`, and whether historical pre-`84e4264b` `openai`/`claude` hashes or legacy `distinct_id`s were purged are unknown.
2. **PostHog, Axiom, Cloudflare, PlanetScale, Clerk, APNs, FCM, and Expo retention and logs.** Only the Axiom dataset configuration in `infra/relay/src/observability.ts` (30-day retention) is visible in code; actual deployed Cloudflare edge logs, PostHog retention, backup retention, and production secrets/config values are unknown.
3. **Deployed hosted web (`app.t3.codes`) and release build flags.** Build-time variables (`__T3CODE_BUILD_RELAY_CLIENT_OTLP_TRACES_*`, `VITE_RELAY_OTLP_TRACES_*`, `EXPO_PUBLIC_OTLP_TRACES_*`) are injected during CI release builds, not hardcoded in the repo.
4. **Third-party coding-agent provider behavior.** What Claude, Codex, Antigravity, Cursor, Muse, Grok, OpenCode, Pi, Kiro, fx, or cloud speech providers log or retain on their own servers is outside this repository.
5. **Installed local version.** No local T3 Code installation, binary, database, or live network traffic was inspected.
6. **Shallow git clone.** `t3code-source` is grafted at `b51399fb`, so telemetry commits older than that graft point cannot be traced locally.
